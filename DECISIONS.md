## n0: Foundation node complete. Clean-clone gate verified end to end:
- **Did:** Foundation node complete. Clean-clone gate verified end to end: npm ci && npm run build && npm test all pass (73 tests, 2 files), plus npm run typecheck. Created every shared manifest so no sibling ever edits one: package.json (bins offstage -> dist/cli/index.js and offstage-mcp -> dist/mcp/index.js; ALL project deps pre-installed and lockfile committed), tsconfig.json + tsconfig.build.json, vitest.config.ts, .gitignore (Rudder entries preserved verbatim, plus node_modules/dist/.offstage/coverage). Wrote src/contract/index.ts (the lane+result contract), src/contract/artifacts.ts (run dirs + result.json persistence), tests/contract.test.ts (50 tests), tests/artifacts.test.ts (23 tests), and a real README.md stating the routing thesis (offstage routes over existing substrates, it is not a new one), the three lanes, and a per-piece Status table. Empirically verified every pre-installed dependency imports AND typechecks under NodeNext ESM (plist v3 + @types/plist, fast-xml-parser, execa, commander, zod, @modelcontextprotocol/sdk) so no sibling discovers a broken import. Also verified that tests/fixtures/** is excluded from BOTH vitest collection and the TS program, by dropping in a Playwright-style fixture importing an uninstalled package and confirming test+typecheck stay green.
- **Interfaces:** src/contract/index.ts exports: type Lane ('headless'|'container'|'vm') + LANES + LaneSchema; type LaneStatus ('passed'|'failed'|'errored'|'skipped') + LANE_STATUSES + LaneStatusSchema; type ArtifactKind + ARTIFACT_KINDS + ArtifactKindSchema; interfaces LaneArtifact, LaneFailure, LaneRequest {cwd, command[], env?, timeoutMs?, artifactsDir}, LaneResult {lane,status,exitCode,startedAt,durationMs,artifactsDir,logPath,artifacts[],failures[],diagnostics[]}, LaneAvailability {available,reason?,fix?}, LaneRunner {lane, isAvailable(), run(req)}, RouteDecision {lane,reason,confidence,signals[]}; schemas LaneRequestSchema, LaneResultSchema, LaneArtifactSchema, LaneFailureSchema, LaneAvailabilitySchema, RouteDecisionSchema; helpers parseLaneResult, safeParseLaneResult, isLaneResult, parseLaneRequest, describeValidationError, isInside, statusFromExitCode, createLaneResult, skippedResult, exitCodeForResult. src/contract/artifacts.ts exports: OFFSTAGE_DIR, RUNS_DIR, RESULT_FILENAME, RunDir, makeRunId, allocateRunDir, artifactPath, toRepoRelative, writeResult, readResult, listRunIds. PATH CONVENTION (schema-enforced, documented in README + module header): LaneRequest.cwd, LaneRequest/LaneResult.artifactsDir, LaneResult.logPath and artifacts[].path are ABSOLUTE HOST paths, and logPath/artifacts[].path must be INSIDE artifactsDir; LaneResult.failures[].file is REPOSITORY-RELATIVE POSIX, relative to cwd, never absolute, no '..' escape. Use artifactPath()/toRepoRelative() to produce accepted values. LANE CONTRACT RULES: isAvailable() never throws and never mutates the world; run() never throws (return status 'errored' with diagnostics); run() never falls back to the real screen (return skippedResult(lane, artifactsDir, availability)). exitCodeForResult: passed 0, failed -> command's code or 1, errored 70, skipped 69. BUILD CONVENTIONS siblings must follow: ESM + NodeNext, so relative imports keep the .js extension; verbatimModuleSyntax is ON, so types must be imported with `import type`; vitest globals are OFF, so import describe/it/expect from 'vitest'; `npm run build` uses tsconfig.build.json (rootDir src -> dist, emits), while tsconfig.json is the noEmit typecheck/editor config that additionally covers tests/.
- **Follow-ups:**
  - Two tsconfigs by necessity: tsconfig.json (noEmit, covers src+tests) and tsconfig.build.json (rootDir src -> dist) — The node prompt asked for one tsconfig with rootDir src AND include src+tests, which tsc rejects (TS6059: tests/ is not under rootDir). Splitting is the standard resolution and keeps bin paths at dist/cli/index.js rather than dist/src/cli/index.js. No sibling needs to touch either file; `npm run build` and `npm run typecheck` both just work.
  - commander pinned to ^14 and execa to ^9 instead of latest — commander@15 requires Node >=22.12 and execa@10 requires Node >=22, which would silently break the stated Node 20+ target declared in engines. The pinned majors are current, maintained, and Node 20 compatible. Revisit only if the project raises its Node floor.
  - @types/plist kept alongside plist@^3 rather than moving to plist@^5 [out of lane] — plist@5 ships its own types, which would make @types/plist redundant and potentially conflicting. Staying on plist@3 + @types/plist@3 matches the specified dependency set and was verified to typecheck and run under NodeNext ESM. n5 (entitlements probe) should import it as `import plist from 'plist'`.
  - npm 11.16 leaves esbuild/fsevents postinstall scripts unapproved on npm ci [out of lane] — `npm ci` prints an allow-scripts warning for esbuild and fsevents. Verified harmless here: esbuild resolves its platform binary via optionalDependencies and vitest runs fine. n9 (integration/clean-clone) should confirm the same holds in whatever CI environment it targets, since a different npm config could make it fatal.
  - LaneResult path containment is enforced, not advisory [out of lane] — parseLaneResult rejects a logPath or artifact path that is not inside artifactsDir, and rejects an absolute failures[].file. This is intentional so run directories stay self-contained and failure paths stay host/guest portable, but lane authors who hand-build paths instead of using artifactPath()/toRepoRelative() will hit it. Flagging so n2/n3/n4 use the helpers rather than working around the schema.
