## n4: the 2-VM ceiling is enforced per repository by default, not per host
- **What:** `src/lanes/vm/slots.ts` implements the Virtualization.framework 2-guest ceiling as lockfiles at `<repo>/.offstage/vm-slots/slot-{0,1}.lock`, per the node prompt's "a simple local semaphore/lockfile under `.offstage/`". `OFFSTAGE_VM_SLOT_DIR` repoints the semaphore at one absolute path so the ceiling becomes genuinely host-wide.
- **Why:** The ceiling is a property of the *host* — Apple refuses to start a third concurrent macOS guest — but `.offstage/` is per-repository, so two checkouts each get their own pair and can between them ask for four guests. The env var is the escape hatch, and the module header says so. **n6 (CLI) and n9 (e2e) should be aware**: any doctor output or multi-repo test harness that cares about the real ceiling must set `OFFSTAGE_VM_SLOT_DIR`. Slots are reclaimed when the owning pid is dead on this host, or aged out after 6h (above the runner's 2h watchdog), and released on every error path including the catch-all.

## n4: VM-lane failure paths come from stripping the guest checkout prefix
- **What:** `guestPathToRepoRelative()` turns `/Users/admin/tart-runner/<run-id>/src/App/Foo.swift` into `App/Foo.swift`, and returns `null` rather than guessing when a path cannot be proven repo-relative.
- **Why:** `run-xcode.sh` rsyncs the read-only source share to `$HOME/tart-runner/<run-id>/src` inside the guest and builds there, so *every* path in `xcodebuild.log` is a guest path that does not exist on the host. This is precisely why the n0 contract requires `failures[].file` to be repository-relative. Consequence worth knowing: `Result.xcresult` "Failure Message" nodes carry only a bare basename (`LoginUITests.swift:42`), which is not reliably repo-root-relative, so the xcresult parser deliberately emits no `file` for those and the log parser supplies it during merge. No invented paths.
